# React/Vite and Terraform quality audit

Date: 2026-09-04  
Scope: `src/**`, root web configuration, generated Data Connect packages,
`terraform/**`, and the web/configuration tests.

This is a classification report, not a deletion approval. The working tree is
shared and contains unrelated edits. The recommendation is to retain the
most complete implementation per boundary, archive only after caller and
deployment checks, and discard generated or proven-dead copies from source
control rather than deleting production behavior by filename.

## Evidence snapshot

- `npm run lint` passes (`tsc --noEmit`).
- `npm run build` passes and emits lazy route chunks, but still warns about
  chunks over 450 kB; the largest emitted chunk in this run was
  `Logger-wVsiYU8G.js` at 675.88 kB.
- `terraform fmt -check -recursive terraform` passes.
- `terraform -chdir=terraform validate` is currently blocked by the installed
  Google provider failing its plugin handshake, not by an HCL diagnostic.
- `src/test/**` contains useful contract tests for discovery identity, cart
  snapshots, HTTPS merchant handoff, and schema validation. There is no
  configured Vitest/Jest script for these TypeScript tests, so test execution
  ownership is unclear and must be fixed before relying on them as a web gate.
- `terraform/tfplan` is a 20 KiB ZIP/binary plan generated by another
  Terraform toolchain. It is not portable source and should not be reviewed as
  the infrastructure definition.

## Generated and duplicated Data Connect output

`src/dataconnect/**` is a generated browser SDK package referenced by the
workspace dependency `@firebasegen/spresso-connector`; several web pages import
it directly. It is operationally present, but it conflicts with the approved
Firestore-first launch boundary and should not become a second source of truth.

| Path | Classification | Recommendation |
| --- | --- | --- |
| `src/dataconnect/**` | Generated client / legacy-exploratory | Retain temporarily because active web imports and the Wasm global bridge depend on it. Freeze hand edits, document generation input, and migrate callers to the approved boundary before archiving. |
| `functions/src/dataconnect/**` | Generated Functions source dependency | Retain temporarily: `functions/src/catalog.ts` and `functions/src/users.ts` import it and `functions/package.json` copies it during build. It is not handwritten feature logic. Regenerate from the authoritative Data Connect schema, then isolate or remove when those functions no longer use Data Connect. |
| `functions/lib/dataconnect/**` | Build output | Discard from source control if tracked; it is produced by `functions` build and is byte-identical to `functions/src/dataconnect/**` for the generated files. Never edit it directly. |
| `server/dataconnect/**` | Separate generated Admin SDK copy | Keep only while `server/inventory.ts` imports it. That server path is an inventory-named legacy adapter and should be removed or rewritten behind the discovery provider boundary before this copy is archived. |
| `src/dataconnect/README.md`, `.guides/**` | Generated documentation | Archive with the generated package once no active caller remains; regeneration will recreate them. |

The three generated trees are not independent implementations. The evidence
is identical generated hashes between `functions/src/dataconnect/**` and
`functions/lib/dataconnect/**`; `server/dataconnect/**` is a separate admin
flavor; `src/dataconnect/**` is the browser flavor. Keep one generated output
per runtime until migration, then remove the runtime-specific copy with its
last caller.

Terraform is not a duplicate of Firebase configuration: it intentionally
manages selected Google Cloud boundaries while `firebase.json` manages Hosting,
Firestore, Storage, Auth configuration, and Functions rewrites. The cleanup
target is undocumented overlap and stale service assumptions, not wholesale
deletion of either system.

## Keep/archive/discard sequence

1. Keep `src/App.tsx`, active route pages, domain contracts, tests, and the
   current Firebase/Vite configuration as the web companion reference.
2. Run exact GitNexus upstream impact for the React `WardrobePage`,
   `NavigableListDetailPaneScaffold`, and every Data Connect import before
   moving anything. GitNexus cannot target the `src/db` directory directly;
   its exact source-level caller is the dynamic `require()` in
   `server/apifyService.ts:143`, confirmed by text search and the boundary
   contract test. Treat `UNKNOWN` as unresolved and confirm with text search.
3. Archive unreferenced handwritten pages and adapters in one reviewable web
   cleanup change; do not mix that change with Android or Terraform edits.
4. Freeze generated packages, record their generator/schema source, and
   migrate callers before removing any runtime copy. Never hand-edit generated
   JavaScript or declaration files.
5. Remove `terraform/tfplan` from source control only after exporting its audit
   metadata and regenerating a compatible plan. Do not run `git clean` or broad
   recursive deletion.
6. Re-run web lint/build/tests, Terraform format/validate/plan, and
   `gitnexus detect-changes --scope compare --base-ref main` after each isolated
   slice. A clean graph result must be compared with the baseline; a partial or
   truncated result is inconclusive.

## Final recommendation

The retained React implementation is the most feature-rich web surface and
should remain a frozen companion/parity reference while Android/KMP is built.
The strongest React cleanup wins are the proven-dead `WardrobePage` and the
unused list-detail scaffold. `src/db` is stale and should eventually be
removed from the server path, but it is not currently dead: the Apify category
feed still calls it. Generated build output and the binary Terraform plan are
separate cleanup candidates. Terraform itself should be retained but treated as a partial
approved-boundary definition, not as proof of a deployed backend. Generated
Data Connect copies should be reduced only after their active callers are
migrated and verified.
